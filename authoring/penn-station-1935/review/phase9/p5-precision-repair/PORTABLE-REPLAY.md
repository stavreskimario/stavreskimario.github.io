# Recovery and replay limits

`python3 recover_evidence.py --out /absolute/fresh/review-receipts` extracts every indexed gzip losslessly and verifies compressed/decompressed hashes before writing. It does not execute a test or modify website assets.

The exact executed helpers are retained as compressed originals. The three readable `source/*.mjs` files are path-only portable derivatives. They require the existing pinned tools and source inputs; they were syntax checked, not rerun. Set `PENN_TOOLS`, `PENN_REPO_ROOT`, `PENN_WORK_ROOT`, `PENN_PRECISION_OUT` and `PENN_PRECISION_PROOF_DIR` to absolute paths. The output and proof folders must be external; repair requires fresh folders. `node source/repair_precision.mjs` then performs the same pinned eight-owner repair. `node source/verify_precision.mjs` verifies the written candidates using the same source controls and frozen standard modules.

The work root must supply the exact raw source model25bc, standard standalone full4f89/lowbde7 modules, their thirteen KTX2/two GI files, curve manifestd776, source flatba851, source adjacency/flat manifests, the held summary0962 and selection80569 in the relative directories recorded by the receipts. These large binaries are deliberately omitted from this compact review packet. Their hashes and the actual preparation/bake/source archives are retained elsewhere in authoring; rebuilding them is a separate pipeline task. This packet does not claim a self-contained full-scene binary replay.

No new architecture is generated by these helpers. They batch and losslessly transport existing exported Blender geometry. Historical P5 identity/radius/fabrication and upper-haunch qualifications remain in the source checkpoint. Native/staging/publication results are separate root-owned evidence, not asserted here.
